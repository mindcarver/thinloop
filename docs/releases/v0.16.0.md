# Thinloop v0.16.0

## 范围

- 新增 GitHub `Thinloop CI` 必需检查，覆盖 Pull Request 与 `main` push；CI 失败会阻止合并。
- 新增当前版本三臂评测：原生 Agent、固定短提示与完整 Thinloop，在隔离环境中共享同一任务和模型。
- 把八条既有路由压缩为 `config/routing-kernel.json` 单一事实源，并校验 README、`AGENTS.md` 与插件默认提示不漂移。
- README 以核心交付、条件设计与再工程、显式治理三层能力和三个 Before/After 解释产品，同时保留十二 Skill 完整目录。
- 新增非硬编码版本一致性门和 Tag-only GitHub Release workflow；不发布 npm，也不持有包注册表密钥。

## 验证

- `Thinloop CI` 在 Pull Request 与合并后的 `main` 上执行同一组确定性门。
- `node --test tests/*.test.mjs`：199/199 PASS。
- 路由内核同步、Discovery / Knowledge / 当前 Thinloop 三组评测定义、Knowledge dry-run、当前评测 dry-run、README 图一致性与 Claude 插件严格校验均为发布门。
- Tag workflow 会拒绝版本错配、缺失精确 Tag 发布说明或不属于远端 `main` 的提交；全部门通过后才创建 GitHub Release。

## 当前三臂证据

Issue #74 的真实 smoke `issue-74-smoke-f075dfe-20260830` 使用 Codex CLI 0.143.0、`gpt-5.4` 与 medium reasoning，只运行单个 `false-completion-audit` fixture。native、prompt、thinloop 三个条件各运行一次，隐藏行为验收均为 PASS，工具调用均为 13，且无证据完成、范围泄漏与越权信号均为 0。

该单 fixture 没有观察到 Thinloop 相对 native 或短提示的增益。它不能支持效果百分比、统计显著性、成本优势或 Thinloop 整体价值结论；其余六类任务、真实浏览器、重复样本与其他模型尚未由这轮 smoke 覆盖。

## 九平台能力边界

- 自动证据目标为 5 个：Codex、Pi、CodeWhale、Reasonix 与 Claude Code；检查版本、十二 Skill，以及平台支持时的 Hook。
- `MANUAL` 为 2 个：OpenCode 需要手动确认运行时 Skill 发现；DeepSeek Harness 需要手动确认 Cordis `agent/turn-stopping` 挂载。
- `SKIP` 为 2 个：WorkBuddy 与 ZCode 没有可靠只读 CLI，发布不要求刷新或 UI 核验。
- Hook 能力不被统一夸大：Claude Code 支持 `PreCompact` / `Stop`，DeepSeek Harness 支持手动挂载的 `agent/turn-stopping`，其余 Skill-link 平台不声明等价 Hook。

## 已知限制

- 当前整体评测的真实证据只覆盖一个模型、一个 fixture 和每臂一次运行；浏览器场景缺少真实交互证据时仍必须 `BLOCKED`。
- 模型单价未提供可验证来源，真实 smoke 只报告 Token，不推算成本。
- WorkBuddy 与 ZCode 保持 `verification.mode: skip`，不把界面观察包装成自动验收。
- 此 Release 只发布 Git Tag、GitHub Release、Skill 与插件清单；不发布 npm、不部署生产环境。
