# 设计品味

UIUX 设计在生成任何视觉产物前共用本参考。它负责生成侧判断：先选定产品形态轨道与方向、封死模板化默认，同时避免把展示站规则机械套用到高密度工具型 Web App。产物验收仍按[页面视觉质量](visual-quality.md)的八维、轮次与证据执行；二者冲突时先统一再继续。

## 生成前方向块

生成线框、视觉稿或原型前，先把五项方向决策写入 UX 契约「视觉方向与系统增量」。说不出任一项时不得开始生成；说不出方向的生成必然回落均值。首项必须显式声明**产品形态轨道**，在以下两轨中二选一（复合产品按页面族分别声明）：

- **展示/营销/内容型 Web**：官网、着陆页、品牌展示、编辑出版与营销专题，重叙事张力、情绪辨识与转化节奏；
- **高密度工具/工作台型 Web App**：SaaS 后台、数据分析看板、监控台、专业编辑器与表单工作流，重扫视效率、首屏信息密度与操作确定性。

五项方向决策：

- 领域、产品形态轨道与气质：产品类别 + 选定轨道（展示/营销/内容型 Web 或高密度工具/工作台型 Web App）+ 结果必须成立的一个词气质（如「克制」「精密」「温暖」）；
- 受众与语气：专家或新手、冷静或活力、高级或实用；
- 动效深度：无 / 仅反馈 / 表达性编排，三选一并说明；
- 布局族：展示型给出命名的分节序列并说明每节构图如何变化，不重复同一行式；工作台型给出导航、指标/筛选带、主工作区与详情抽屉的骨架和聚焦关系；
- 参考锚点：对标的具名系统或作品，来源可核对；无法联网对标时按页面视觉质量的外部对标规则记录。

方向块先于产物存在。产物偏离方向块或跨轨混用规则时，先改方向块或改产物并记录原因，不得事后解释成「风格选择」。清晰局部变更继承现有方向与轨道，只写增量。

## 反模式黑名单

先守住两轨共用硬底线，再按选定产品形态轨道执行对应细则。生成时逐条规避，自审时命中即按对应维度 `FAIL`：

### 两轨共用硬底线（全部产品形态适用）

| 默认 | 为什么是缺陷 | 替代 |
|---|---|---|
| `#000` 压 `#fff` 或低对比灰字 | 刺眼或不可读 | 主题内暖白/浅灰底配非纯黑文字；正文对比度 ≥ 4.5:1、大字 ≥ 3:1 |
| 强调色彩虹 | 无纪律、语义混乱 | 一个主色，至多一个强调色；中性色承担主体 |
| emoji 当图标、项目符或状态点 | 最响的生成物痕迹、跨平台不一致 | 内联 SVG 图标用 `currentColor`，或纯文字 |
| 每个盒子都有投影 | 浑浊、过时的深度 | 大部分平面；阴影稀有而分层，工作台优先细边框与表面阶梯 |
| 单侧彩色边条 | 陈词滥调的装饰 | 完整细边框或面分隔；状态用图标加文字，不只靠颜色 |
| 牺牲无障碍与交互底线 | 触控难按、键盘失焦、动态不适 | 触控目标 ≥ 44×44px（间距 ≥ 8px）、可见焦点环、键盘可达、适配 `prefers-reduced-motion` |

### 展示/营销/内容型 Web 专属黑名单

以下默认在展示/营销/内容型页面中均为缺陷，保留强视觉张力：

| 默认 | 为什么读起来像生成物 | 替代 |
|---|---|---|
| 三个或四个等权重卡片机械并排 | 视线无处落 | 让一个要素领先：更大、更重或独占一行 |
| 整页居中 | 无张力、无层级 | 真实网格上的不对称构图；居中仅作刻意例外 |
| 同一「左文右图」行式重复 | 明显模板化 | 每节构图有意变化 |
| 标题只是加粗正文 | 没有显示层级 | 最大标题至少 2.5 倍正文（≥ 2.5x），短，18–24 字符行长 |
| 拥挤的垂直节奏 | 密集、焦虑 | 分节之间保留慷慨的宏观留白 |

### 高密度工具/工作台型 Web App 差异化约束

工作台与专业 Web App 不得套用展示站审美而牺牲首屏效率，明确允许以下结构化模式：

- **允许等权重结构化组件**：同度量 KPI 指标卡、对比定价格（Pricing Grid）、数据网格与状态看板可合理等权重并排；通过主指标高亮、状态色阶、等宽数字对齐（`tabular-nums`）与清晰区块标题建立扫描层级，不为“非对称”强行破坏横向对比；
- **允许紧凑标题层级**：主标题相对正文可收窄至 `1.35x–1.75x`（如 14px 正文配 20–24px 页头标题），配合字重、面包屑与副标签区分层级，保护首屏信息密度；仍禁止标题与正文同号仅加粗或层级跳级；
- **允许紧凑但有序的信息节奏**：按 4px 阶梯与外距大于内距组织高密度分组，消除无呼吸感的粘连堆叠。

工作台轨道专属反模式（命中即 `FAIL`）：

| 默认 | 为什么破坏工作台效率 | 替代 |
|---|---|---|
| 装饰性大横幅挤占首屏主工作区 | 关键数据与高频操作被推到折线以下 | 紧凑页头加即时筛选/KPI 带，让核心工作区首屏可见 |
| 高频操作仅靠 hover 暴露或藏在多层菜单 | 触控与键盘不可达、扫描成本高 | 主操作明示，次要行操作保持可见或清晰触发入口 |
| 表格/指标缺少数字对齐或无溢出承接 | 纵向扫读困难、撑破整页宽度 | 数值列右对齐与 `tabular-nums`，表格容器独立横向滚动 |

## 文案纪律

界面文案禁用：营销填充词（「赋能」「无缝」「解锁」「极致」）、空洞三连（「强大、直观、美观」）、假结构标签（「SECTION 01」、lorem ipsum、「在此输入标题」）和过度对冲的微文案。写具体的、可验证的事；读出来像新闻稿就删短、写具体。

## 响应式策略（移动优先 vs 纯桌面工具桌面优先）

- **展示/营销/内容型 Web 及面向移动端的通用 Web**：严格执行**移动优先**——基础样式即窄屏布局，更宽的屏幕用 `min-width` 逐层叠加，禁止桌面优先再回头补移动端。`max-width` 属性用于阅读行长、容器上限与图片约束，不受此限制。
- **纯桌面专业工具/高密度工作台型 Web App**（如多栏看板、复杂表格后台、专业编辑器）：允许采用**桌面优先**策略，围绕主力桌面视口建立高效分栏与信息密度；但必须在 UX 契约中明确**窄屏可用或优雅降级策略**（例如侧边栏折叠为抽屉、数据表独立横向滚动、保留关键查看/审批能力且不产生整页水平溢出；若产品契约明确不支持窄屏编辑，提供清晰的窄屏降级提示与安全只读/退出路径）。
