# Web 平台设计原则

聚焦设计与产品体验路径共用本参考。以下为面向 Web 的平台级设计原则，由本项目自写提炼，方法灵感来自公开官方指南（Apple Human Interface Guidelines：<https://developer.apple.com/design/human-interface-guidelines/>；Material Design：<https://m3.material.io/foundations>），**不复制其原文**。无障碍要点吸收自 plugin87/ux-ui-agent-skills（MIT）的 accessibility 规则。

## 交互与输入

- 触控目标至少 44×44px、相邻间距至少 8px；鼠标、触控、键盘三种输入都要可完成同一任务。
- 焦点必须始终可见；键盘顺序与视觉顺序一致，模态可关闭、焦点可返回。
- 表单尊重浏览器自动填充与原生校验语义；错误就地关联字段并说明恢复方法。
- 惯性滚动、吸顶吸边等行为跟随平台惯例，不发明反直觉滚动。

## 主题与媒介

- 深色模式不是反色：表面层级与语义令牌切换（见[设计令牌](design-tokens.md)），每个状态两种模式都核对。
- 字体栈尊重系统字体偏好；正文不小于 12px，行高约 1.5。
- 动效遵守 `prefers-reduced-motion`；提供等价的非动效反馈路径。

## 无障碍底线（每项都可测试）

- 正文对比 ≥4.5:1、大字 ≥3:1；状态与错误不只靠颜色传达（图标+文字）。
- 图片有替代文本或等价含义；纯装饰对辅助技术隐藏。
- 图标按钮必须有可访问名称；交互组件用语义元素构建，不用 `div` 仿造。
- 信息结构用真实标题层级表达，不跳级。

## 平台一致性

- 同一产品内相同操作用相同模式（同一删除确认、同一空态表达）；跨页面术语不漂移。
- 原生控件优先：能用平台既有控件表达的，不自绘替代品。
- 响应式遵循[设计品味](design-taste.md)的移动优先基准，宽屏逐层叠加而非缩放。

## 使用方式

这些原则是检查面，与八维表（[页面视觉质量](visual-quality.md)）配合：八维按维度验收，本参考按平台惯例与无障碍底线验收。冲突时，可测试的无障碍要求优先于风格偏好。
