# 页面视觉质量

UIUX 设计、QuickDev 的真实页面差异及 `scd-ui-polish` 共用本参考。八维标准与自审只在此维护；页面旅程、独立验收和人工确认继续遵循各自原契约，不另建发布门。

## 目标与边界

以 Awwwards、Webby Awards、FWA 优秀作品的完成度为质量参考，形成符合产品用途、品牌和内容密度的精细表达。获奖名称不是统一风格或验收认证，不承诺“没有任何改进空间”。可读性、操作效率、无障碍和性能不得因装饰退步。

优先沿用已确认的视觉稿、设计系统和品牌约束。需要探索方向且可联网时，实际查看 1–3 个相近产品或内容密度的优秀作品，记录来源和具体借鉴点；不能只列奖项名称。无法查看时注明未完成外部对标，仍可依据已确认来源工作，不虚构参考或获奖结论。

在现有记录中简述统一方向：气质、排版、色彩与对比、布局与留白，以及一个与内容相关的辨识点。清晰局部修改继承现有方向，只说明增量，不扩大成整体改版、完整设计系统或装饰性动效。

## 修改前基线与视口

已有页面在修改前用真实浏览器查看内容、操作关键控件并保存基线截图，记录页面/路由、内容或数据条件、视口宽高、滚动位置、交互状态和目标版本。用户已提供可核对基线时可以复用并注明来源；没有历史基线不得事后重建成“修改前截图”。

页面级设计或优化默认检查桌面 1440px、平板 768px、手机 390px 宽，并记录实际高度；用户指定视口或产品既有断点可以替代，写明理由。局部修改只覆盖受影响组件及相关布局；没有布局变化的尺寸不重复造图，但必须核对适用的重排、换行与触控行为。

新页面没有历史基线时标记 `N/A：新页面`；设计阶段保留首轮可渲染稿作为迭代基线，实施阶段对照已确认视觉 ID。不得为了填齐前后图捏造旧页面。

## 八维检查

| 维度 | 阈值与检查方向 | 高频反模式 |
|---|---|---|
| typography / 排版 | 标题、正文和辅助信息层级；字体气质、字重、字号、行高、行长与中英文混排。正文行长 45–75ch；行高正文约 1.5、大标题不超过 1.25；UI 用一族字体，编辑内容可用衬线，代码等宽；h1 每页一次且不跳级。 | 标题只是加粗正文；灰上灰；正文小于 12px。 |
| whitespace / 留白 | 一致的间距、对齐、分组和阅读节奏。间距走 4px 基数阶梯；外距大于内距（容器边距 > 元素间隙 > 元素内边距）；相关元素靠得更近。不机械放大所有间距，消除无意义空洞。 | 机械放大所有间距；拥挤的垂直节奏。 |
| visual_hierarchy / 视觉层级 | 首屏主题、阅读焦点、内容顺序、主次操作与区块关系。每节一个焦点；主次操作在尺寸或权重上可区分；分节构图有意变化。 | 等权重卡片并排；整页居中；同一行式重复。 |
| color / 色彩 | 背景、文字、强调色、状态色职责清晰且一致。正文对比至少 4.5:1、大字至少 3:1；一个主色至多一个强调色；不只依赖颜色传达状态。 | 纯黑压纯白；强调色彩虹；灰上灰。 |
| motion / 动效 | 用于状态、注意力或空间关系，节奏一致且流畅；检查减少动态效果偏好。无需动效时记录理由，不为过表添加动画。 | 一个时长包打所有过渡；动画 width/height；无减少动态效果适配。 |
| micro_interaction / 微交互 | 实际操作按钮、链接、表单、导航与展开组件；核对适用的 hover、focus、active、disabled、loading 及反馈。触控目标至少 44×44px 且相邻间距至少 8px；禁止 0ms 突变。 | 仅 hover 的交互；移除焦点环。 |
| responsive / 响应式 | 布局重排、字号、间距、图片裁切、导航与阅读顺序；检查溢出、遮挡和触控区域。基础样式即窄屏布局，宽屏逐层叠加。 | 桌面等比缩小；桌面优先再补窄屏。 |
| originality / 辨识度 | 用符合产品内容的构图、排版、素材和细节形成特点；不偏离已确认视觉语言。 | emoji 当图标；单侧彩色边条；模板化装饰。 |

八维都要考虑；未触发维度记录 `N/A` 和具体原因。无视觉变更或无关区域不得借此扩展修改范围。生成侧完整禁令以[设计品味](design-taste.md)的反模式黑名单为准；黑名单命中计入对应维度 `FAIL`，不以风格偏好辩解。

## 有限自审与修正

设计产物和真实页面均至少完成两轮实际检查；检查不要求每轮都产生代码改动：

1. 第一轮检查整体布局、排版、层级和色彩，选择最影响结果的至多三个具体问题修正。
2. 第二轮在更新后的产物或页面检查细节、响应式、交互状态及新增退步；按八维复核并保存证据。
3. 第二轮仍有明确问题时增加第三轮，优先修正阻塞约定验收的问题。第三轮仍未解决时记录具体差距和原因，停止无界打磨；必需项未通过不能声明完成。

每轮记录实际目标版本、视口/状态、观察、修改或无需修改的理由、重查结果与证据引用。首轮记录还须包含生成前方向块（或其增量）；后续各轮记录方向决策的变更与原因。浏览器刷新后确认修改已生效；截图不能证明已操作交互，代码检查和构建成功也不能代替实际渲染检查。

设计阶段检查项目内视觉产物及可操作原型，不要求尚不存在的生产页面。实施阶段必须检查真实应用。缺少阶段必需的浏览器、状态或证据时记录 `BLOCKED`，不能由自评分数或文字描述替代。

## 同条件对比与交接

已有页面的前后截图尽量保持相同页面、内容、视口、滚动位置和交互状态；有差异时注明原因及其比较限制。页面级优化至少展示桌面和手机首屏前后对比，重要改动补充局部；局部任务只需对应区域的可核对对比。新页面按上述 `N/A` 规则展示设计迭代或设计与实现对比。

在现有 UX 契约或 Issue 中链接基线、各轮证据和前后图，不另造强制报告或复制页面验收矩阵。交接说明设计方向、主要修改解决的问题、八维观察结果、实际视口与交互、剩余不足及未验证部分；维度结果使用 `PASS`、`FAIL`、`BLOCKED` 或带理由的 `N/A`。`PASS` 只表示约定范围内有证据支持，不表示获得奖项或全部主观偏好已满足。
