# SCD UIUX 设计

开始执行前必须先读取并遵守[步骤沟通](../scd-quickdev/references/step-communication.md)；直接调用本技能也适用。

让 Web 体验清晰到足以评审与实施，但不把每次界面调整变成设计项目；生产代码交给 `scd-quickdev`。设计或实施前读[计划确认契约](../scd-quickdev/references/planning-contract.md)（只读查询/审计不建计划，保持更窄治理权限）。

## 选择最轻量且充分的路径

检查请求与仓库后内部择路（除非被问及方法，否则不公布路径名）：

- **直接实施：** UI 变更及可观察结果已清晰。无需完整UX设计，交给QuickDev确认具体方案和实施计划。
- **聚焦设计：** 单个旅程、界面或交互需设计，只解决并保留该切片所需交接。
- **产品体验：** 重 UI 型 0 到 1 交付需一致体验；要求产品核心已稳定，小型 UI 变更也不会因此进入“产品体验”路径。
- **体验验证：** 对现有 UX 契约或原型执行只读完整性、一致性、无障碍或就绪审计。

## 从产品事实和仓库事实出发

提问前先读仓库说明、关联 Issue、已确认 `.scd/product/prd.md` 精确版本、现有 UI/设计系统、接口契约与参考图，可行时查看运行态。进行“产品体验”时，产品核心必须已经明确主要用户、问题、下一交付、规则、边界与验收（否则用 `scd-discovery`；不在 UX 中重建产品契约）。

核心稳定后可与 `scd-architecture` 并行，但前后端实施前须通过共享接口契约统一操作、数据、错误、权限与术语。UX 发现已确认行为、范围、权限、数据/隐私边界、不可逆操作或验收需调整时，只把该变更返回 `scd-discovery`。本技能仅覆盖桌面与响应式移动 Web，原生端需求说明边界并停止。

## 确定体验切片

聚焦最小完整用户旅程，仅在仓库证据不足时一次询问一个实质决策并附推荐与理由（由用户做产品/品牌取舍）。

## 先建模行为，再打磨外观

开展聚焦设计或产品体验前，阅读 `references/experience-contract.md`、按[设计方法论](references/design-method.md)组织切片并遵循[Web 平台设计原则](references/platform-principles.md)，覆盖已触发的旅程/恢复路径、界面与层级、状态转换、交互反馈、响应式与无障碍、视觉增量、接口需求与追溯——每项需求须落到界面或有意非 UI 行为，不为凑数添加装饰界面。

默认复用现有设计系统；修改或扩展存量项目（Brownfield）前，先按[设计令牌](references/design-tokens.md)扫描仓库现有 CSS 自定义属性、Tailwind 配置/主题变量与组件库变体，记录存量令牌基线后再写增量。

## 形成可实施的视觉交付

需参照视觉方向、配色、字体、图标、图表或动效时，检索内置知识库：`node <skill-root>/scripts/search.mjs <2-5 个英文设计关键词> [--domain <域>]`（域见 `--list-domains`；优先传入英文设计关键词，脚本内置高频中文设计词同义映射兜底）。单次查单一意图，空或离题时换词重试一次，无命中如实报告而不虚构；入契约时注明来源域与条目。

创建或验证视觉产物前读 `references/visual-evidence.md`，生成前按[设计品味](references/design-taste.md)选定轨道、写出五项方向块并排查反模式黑名单与硬底线；同时执行共用[页面视觉质量](references/visual-quality.md)（已有页面纯打磨可独立用 [scd-ui-polish](../scd-ui-polish/SKILL.md)）。

- 文案、颜色、间距或局部组件变更用简洁增量说明，不强制扩大成设计项目。
- 显式 UIUX 设计、重要新页面、重要用户流程或整体改版必须生成项目内可渲染的视觉产物：用稳定视觉 ID 映射界面/旅程/视口/保真度/文件；响应布局有变化时覆盖代表性桌面和窄屏视口；低保真默认纯灰度 HTML 线框，复杂有状态交互在 `.scd/ux/<slug>/prototype/` 提供基于三层 DTCG CSS 自定义属性和内嵌状态切换条的轻量 HTML 原型；外观/密度属关键验收时补高保真。
- 不强制使用 Figma；外部设计工具链接仅作上游来源并需导出项目内渲染文件，原型需标非生产。

视觉产物与 UX 契约冲突时保持 `status: draft` 并先统一，不得静默选一。重大新页面、整体改版或高成本视觉方向须展示交付并取得一次明确确认后才可设为 `ready`（与 Discovery 组合时并入合并确认；局部设计也须确认具体选择；就绪审查不代替方案批准或开工授权）。还须在契约中单独标记“实现后最终视觉确认”（普通页面/局部变更默认“不需要”；整体改版、高保真品牌或主观布局/密度验收标“需要”并记理由），该标记不阻止设计契约先进入 `ready`，但在确认完成前阻止最终交付和关闭 Issue。

## 统一衔接点与设计状态

按 `references/experience-contract.md` 列出界面显示、操作、状态与示例，复用共享接口契约操作/字段名。UIUX 不得单方面定稿端点或后端所有权，`scd-architecture` 推动需求与前后端约束收敛，统一到一个共享的机器可读接口契约后前后端才算可独立工作；未决衔接点标为阻塞，不要在 UX 产物中复制共享接口契约。

纯只读讨论留对话；实际设计决策和局部增量写入任务计划。需持久交接时优先用现有设计位置，否则从 `assets/ux-contract.md` 创建一份 `.scd/ux/<slug>.md`（视觉放 `.scd/ux/<slug>/visuals/`，原型放 `.scd/ux/<slug>/prototype/`）。未决使用 `status: draft`，就绪后用 `status: ready`（不是第二次产品确认；与 Discovery 组合时由关联 Issue 承载合并确认）。不创建 PRD、前端架构、故事或开发计划。

## 审查就绪度并交接

设为 `ready` 前阅读 `references/experience-contract.md` 完成就绪检查（确保旅程到界面的覆盖闭合、状态/恢复明确、响应式和无障碍要求可测试、视觉产物与原型齐备、所需确认与实现后确认标记已完成且无冲突待定项）。

与 Discovery 组合时送回一次合并确认；交给 `scd-quickdev` 实施时提供产品契约、就绪 UX 契约、视觉文件与原型、实现后确认标记、就绪架构设计与共享接口契约。本技能不得实施生产前端代码。
