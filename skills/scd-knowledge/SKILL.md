# SCD 开发知识

开始执行前必须先读取并遵守[步骤沟通](../scd-quickdev/references/step-communication.md)；直接调用本技能也适用。

保留经验证的经验，不把每次对话变成永久上下文。只有用户明确请求时运行；普通开发期间不得自动调用。沉淀只授权分析候选项，用户确认精确草稿、范围、目标位置及操作后才能写入。不修改其他 Skill、规则、ADR 或 Hook。

## 选择请求的操作与解析知识库

- **沉淀：** 从当前工作或用户陈述提取经验。
- **检索：** 为当前问题搜索项目与个人知识。
- **维护：** 更新、合并、替换或归档现有知识。

项目知识放仓库 `.scd/knowledge/`（含 `INDEX.md`、`entries/`、`archive/`）；个人知识根目录取明确绝对路径或 `<user-home>/.scd/config.json` 的 `knowledge_root`（首次提供时合并写入用户级配置，通过运行时解析主目录）。处理配置、建库或异常路径前读 `references/storage-contract.md`。

## 沉淀知识

分类、去重或脱敏前阅读 `references/knowledge-contract.md`：

1. **准入与障碍：** 从对话、仓库与检查中提炼可复用、很可能改变后续 Agent 决策或行动且满足至少一项障碍的经验（障碍用于评审，不是必需持久字段）：
   - **语义障碍：** 项目语言、缩写或含义无法仅从字面推导。
   - **位置障碍：** 权威入口或职责不在直观搜索路径。
   - **行为障碍：** 反直觉机制、约束或失败模式无法通过普通推理安全推导。
   拒绝通用建议、普通事实、对话摘要、临时状态、个人偏好与一次性指令。
2. **证据与事实匹配：** 必须有支持证据且证据必须与声明匹配——用户明确陈述的实践本身可以作为有归属来源；语义需权威定义，位置需验证具名路径/符号，行为需最小失败、机制与聚焦测试/运行时结果。根据仓库或工具输出验证每个具名路径、符号、方法、命令、配置键和版本（源码搜索可证伪，但不能单独证明运行时行为）。用户明确要求评审已完成交付时，仅以 Issue、PR、发现与验收证据作候选来源（不得自动开始，也不授权写入）。
3. **范围、去重与确认：** 压缩为触发条件、指引、边界、证据与来源（一条充分证据即可直入跨项目；依赖特定仓库则建议项目范围，可移植性不确定时优先项目范围）。检索双方活跃索引：重复跳过、实质改进建议编辑、冲突呈交选择；不能仅因 A 与 B 重叠、B 与 C 重叠就桥接合并。脱敏密钥与不必要个人路径，展示草稿、障碍、预期行为变化、范围、目标位置与操作并请求一次明确确认；确认后按 `assets/knowledge-entry.md` 与 `assets/knowledge-index.md` 写入并报告变更文件（不暂存/提交/推送）。

## 检索知识

1. 先搜项目 `INDEX.md`，再搜可用个人 `INDEX.md`（一方不可用如实说明并继续另一方，不宣称搜索了双方）。
2. 选择最小相关集合（通常不超过三个条目；除非要求历史/冲突分析，否则不读取 `archive/`），只读匹配条目并优先更具体的项目指引。
3. 应用代码依赖条目前尽量核验仓库事实；陈旧或越界条目不应用，改报理由并提供需确认的维护操作；无匹配直接说明，不制造建议。

## 维护知识与强制边界

- **重复：** 不写入。 **改进：** 必须存在唯一合适目标，保留原边界与最安全具体指引。 **冲突：** 展示旧结论、新证据与边界差异待用户抉择。 **归档：** 移至 `archive/` 标明状态并从 `INDEX.md` 移出。每次更新、合并、替换或归档前都要确认（检索只读）。
- 即使普通确认已给出，也绝不写入凭据、密码、令牌、Cookie、私钥或敏感连接串；目标缺失或不可写时阻塞而不跨范围降级；写入失败不得声称已持久化；保持紧凑，复杂流程建议提升为 Skill；不得在无受控比较下把任务成功归因为知识生效。
