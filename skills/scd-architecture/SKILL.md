# SCD 架构设计

开始执行前必须先读取并遵守[步骤沟通](../scd-quickdev/references/step-communication.md)；直接调用本技能也适用。

把已确认产品行为转化为一致技术设计与可验证共享契约，但不把架构变成每次变更的必经仪式；生产实施交给 `scd-quickdev`。设计或实施前读[计划确认契约](../scd-quickdev/references/planning-contract.md)（只读查询/审计不建计划，保持更窄治理权限）。

## 选择最轻量且充分的路径

检查请求与仓库后内部择路（除非被问及方法，否则不公布路径名）：

- **直接实施：** 变更符合现有边界和契约。无需完整架构设计，交给QuickDev确认具体方案和实施计划。
- **聚焦设计：** 需设计单个接口、领域映射、模块边界、数据所有权或技术取舍。
- **产品架构：** 0 到 1 系统在产品核心稳定后建立领域、系统与接口基线。
- **架构演进：** 现有系统增量演进；保留基线，只记持久边界变化或已触发风险。
- **架构验证：** 对现有架构或契约执行只读一致性、兼容性或就绪审计。

项目规模本身不足以证明需要“产品架构”，新增一个端点也不足以证明需要重写架构。

## 从产品事实和仓库事实出发

提问前读仓库说明、作为依据的 Issue、已确认 `.scd/product/prd.md` 精确版本、就绪 UX 契约、现有架构/ADR、接口契约、代码边界、依赖锁定版本、最新官方文档（选型或集成外部 SDK/协议时必须查阅，离线/不可达记 `UNVERIFIED`）、测试与部署拓扑，核查实际代码。进行“产品架构”或引入重大新子系统时，先对照已有 GitHub 同类开源方案评估直接复用/适配/借鉴；进行“产品架构”时产品核心必须稳定：存在已确认 PRD 时，由 PRD 负责产品级业务决策；否则由作为依据的 Issue 负责；架构不得发明缺失的产品行为（实质缺口回 `scd-discovery`）。核心稳定后可以与 `scd-uiux` 并行进行，前后端独立实施前，必须通过共享接口契约统一操作、数据、错误、权限和术语。

## 确定设计切片

只展开已触发架构关注点（领域模型/事务、组件边界/所有权、数据流/幂等/失败、共享契约、安全/隐私/可观测性、兼容性/迁移/回滚）。仅在仓库证据无法回答时一次询问一个实质决策；具体技术选择先展示选项、影响、推荐与理由，确认后推进（尤其锁定、兼容、安全隐私与破坏性迁移）。

## 建模领域与系统职责

进行产品架构、演进、持久文档编写或就绪审查时，阅读 `references/architecture-contract.md` 并遵守[工程最佳实践](../scd-quickdev/references/engineering-practice.md) §1 模块化/依赖方向/防腐边界。将已确认规则映射为状态转换所有者、事务与一致性边界、权威/投影/缓存区分、权限信任边界、故障恢复及验收追溯。普通领域模型保存在 `.scd/architecture.md`，只有所有权/生命周期/权限/跨实体不变量或迁移使领域足够复杂时才拆出 `.scd/domain.md`；现有系统仅持久边界变化时更新 `.scd/architecture.md`，重要功能局部设计放 `.scd/designs/<feature>.md`。

## 生成共享的机器可读契约

工作跨越前端、服务、插件、事件、文件或模块边界时，阅读 `references/interface-contract.md`。优先使用仓库现有的契约位置和格式，否则放在根目录中可见的 `contracts/`，选用消费者可解析的机器格式（OpenAPI/GraphQL/AsyncAPI/JSON Schema/Protobuf 等）。架构推动契约收敛但不得单方面定稿接口（不把字段表复制到架构说明）。Markdown 草图不能替代契约：只有在规范契约机器可读、经过真实工具解析并覆盖操作/类型/错误/权限与示例后，边界才可进入 `ready`。

## 最小真实验证与持久状态

设为 `ready` 或完成“架构验证”前，阅读 `references/readiness-review.md`。运行可用格式感知解析/编译、示例/类型/兼容校验与映射核对；仅在必要时用一次性隔离探针验证可行性（不得并入生产入口）。本技能不得编写生产业务代码、执行真实数据迁移、修改在线基础设施或部署；必需解析器或检查无法运行则保持 `draft` 并报告未验证边界。

纯只读讨论留对话；实际设计决策和局部增量写入任务计划。无仓库原生位置时按需从 `assets/` 模板（`architecture-contract.md`、`feature-design.md`、`domain-contract.md`）创建 `.scd/architecture.md`、`.scd/designs/<feature>.md`、`.scd/domain.md`，契约放 `contracts/`。未决用 `status: draft`，就绪后用 `status: ready`；`ready` 表示机械与语义就绪，不是第二次产品确认。

## 路由变更并交接

- 行为、规则、权限、数据/隐私边界、不可逆操作或验收变化返回 `scd-discovery`；体验/视觉/无障碍变化返回 `scd-uiux`。
- 内部且可逆架构选择也须用户确认；破坏接口的变更须与消费者协调兼容性、迁移和回滚。
- 交给 `scd-quickdev` 时提供已确认 Issue、就绪 UX 与架构设计、规范机器契约及已观察验证证据。
