# SCD 测试设计与独立验收

开始执行前必须先读取并遵守[步骤沟通](../scd-quickdev/references/step-communication.md)。直接调用本技能也适用。

先从用户要求、适用仓库说明、已批准产品或任务计划和 Issue 中找出验收依据。保留原始要求、已有验收 ID 和精确的获批版本。Issue 和实现如果缩小或改变了已确认的要求，检查是否存在对应的新批准，不能用当前代码或测试倒推预期。

## 按请求选择用法

| 请求 | 行动 |
| --- | --- |
| 设计测试、制定回归场景或检查验收项是否可测 | 读取[测试设计](references/test-design.md)，交付起始状态、操作、可观察结果、关键反例与验证方式。 |
| 验收功能、检查 PR 是否符合原要求或核对已有测试证据 | 读取[独立验收](references/acceptance-audit.md)，核对目标差异，执行可用的直接验证，逐项给出 `PASS`、`FAIL` 或 `BLOCKED`。 |

用户同时要求设计和验收时，先固定预期再观察目标。能读取的来源先查证；关键预期仍有歧义时，区分能验证的场景和待决项。新产品或相互依赖的未知产品决定交给 `scd-discovery`。

## 与交付衔接

单独调用时返回测试设计或验收报告，允许在隔离环境运行相关检查。已获授权的交付复用现有计划和 Issue，验收结果由 QuickDev 写回同一 Issue。设计阶段的可执行方案与验收阶段已经观察到的结果分别记录。

当本技能用于 QuickDev 的独立验收时，由既有的新上下文验收者执行。分支、提交、发布、合并和关闭继续遵守 [QuickDev 发布契约](../scd-quickdev/references/release-contract.md)。涉及产品或持久测试代码变更时，沿用[计划确认契约](../scd-quickdev/references/planning-contract.md)。
