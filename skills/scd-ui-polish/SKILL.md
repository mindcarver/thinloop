# SCD 页面优化

开始执行前必须先读取并遵守[步骤沟通](../scd-quickdev/references/step-communication.md)；直接调用本技能也适用。

把已有页面打磨至符合产品用途与品牌的精细度，并以真实页面前后对比证明改进；要求实施时直接完成代码交付，不停在建议清单。设计或实施前读[计划确认契约](../scd-quickdev/references/planning-contract.md)（只读查询/审计不建计划，保持更窄治理权限）。

## 检查现有页面

先读 `AGENTS.md`、`CLAUDE.md`、当前任务/Issue、已确认视觉来源与附近组件以确定目标页面与边界。修改存量页面（Brownfield）前，先按[设计令牌](../scd-uiux/references/design-tokens.md)扫描仓库现有 CSS 自定义属性、Tailwind 配置/主题变量与组件库变体，记录存量令牌基线后再规划增量，禁止脱离现有体系另起炉灶。

修改前读取并执行共用[页面视觉质量](../scd-uiux/references/visual-quality.md)：打开真实页面、操作控件、存基线，并在规范审阶段运行零依赖 `../scd-uiux/scripts/dom-audit.mjs` 量化探测硬底线；指出至多三个最影响观感的具体问题与改善方向（不给抽象“高级感”评分）。仅要求评审时保持只读（缺代码可完成评审但不得称已实施；缺页面访问标 `BLOCKED`）。

## 选择视觉增量

沿用既有品牌、设计系统与视觉稿提出统一增量（按共用参考实际对标优秀作品）。局部优化先确认方案与计划；整体改版、高成本视觉方向或改 UX 契约交 [scd-uiux](../scd-uiux/SKILL.md)，不借视觉优化擅改功能或业务规则。

## 实施与复查

要求改仓库时进入 [scd-quickdev](../scd-quickdev/SKILL.md)，以一个中文 Issue 固定边界并复用本技能收集的基线与视觉方向（不重建第二份计划），由 QuickDev 负责工程验证、真实页面验收、独立子智能体验收与交付。交付中持续执行共用参考的八维检查、至少两轮自审、必要第三轮及同条件对比，只改有证据支持的范围内问题；需用户最终视觉确认时沿用 UX 契约标记。

## 展示优化结果

展示实际页面与同条件前后图，列明解决的问题、检查视口与交互、轮次与八维结果及剩余差距；仅报已观察证据，缺失部分标未验证或阻塞，不自称“获奖级”或“无改进空间”。
