# SCD 页面优化

把已有页面优化到与产品用途、内容和品牌相符的精细程度，并用实际页面和前后对比证明改进。独立调用本技能即可开始；用户要求实施时继续完成代码交付，不停在建议清单。

## 检查现有页面

先读适用 `AGENTS.md`、`CLAUDE.md`、当前任务或 Issue、已确认视觉来源和附近组件。确定目标页面与修改边界；可从当前上下文确定时不重复询问。

修改前读取并执行共用的[页面视觉质量](../scd-uiux/references/visual-quality.md)，实际打开页面、操作主要控件、保存基线。指出至多三个最影响观感的具体问题，以及各自的改善方向，不能只给抽象“高级感”评分。

用户只要求评审时，保持只读，交付观察与建议。缺少代码访问时可完成已授权评审，但不得声称完成实施；缺少必需页面访问时明确 `BLOCKED` 及缺口。

## 选择视觉增量

沿用有效的品牌、设计系统和已确认视觉稿，提出统一的排版、色彩、布局和辨识点增量。按共用参考实际查看适用的优秀作品，不把奖项名称当作已完成对标。

明确局部优化直接推进；整体改版、高成本视觉方向或改变已有 UX 契约的工作先使用 [scd-uiux](../scd-uiux/SKILL.md) 处理必要设计与已有确认门。不要重建 PRD，也不要因为追求视觉效果擅改内容、功能或业务规则。

## 实施与复查

用户要求修改仓库时进入 [scd-quickdev](../scd-quickdev/SKILL.md)，以一个中文 Issue 固定结果和边界，复用本技能已收集的基线、视觉方向和来源，不重复调查或创建第二份计划。QuickDev 负责生产代码、工程验证、真实页面验收、独立子智能体验收和普通仓库交付；本技能不另定义这些门槛。

在该交付中持续执行共用参考的八维检查、至少两轮自审、必要第三轮和同条件对比；只修改有证据支持且在范围内的问题。已确认视觉稿约束实施，不能借优化重新设计。需要用户最终视觉确认时沿用 UX 契约标记，不用自审或独立验收代替。

## 展示优化结果

展示实际页面和相同条件的前后图，说明主要修改解决的问题、实际检查的视口与交互，以及剩余差距；引用原 Issue 或 UX 记录中的轮次和八维结果。只报告已观察证据，缺失部分保持未验证或阻塞；不得自称“已经获奖级”或“没有改进空间”。
