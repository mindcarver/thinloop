# 步骤沟通

全部 Thinloop 技能共用本规则，直接调用任何子技能也适用。技能启动时读取；每个有意义的步骤开始前，在用户可见的进度消息中展示「第几步、当前步骤、做什么、为什么」，不得只藏在计划、工具日志或最终总结里。

## 展示方式

默认使用带图标的紧凑 Markdown 引用块，以左侧竖线分组，使用普通正文字号和字重：

```markdown
> 🧪 第 3 步：验证修改\
> 🎯 做什么：运行本次变更的相关测试和仓库检查。\
> 💡 为什么：确认修改解决了目标问题，并检查是否影响现有行为。
```

实际发送时直接输出引用块，不要套代码围栏。三项各占一行；前两行末尾用反斜杠保留换行。不使用等号边框、Markdown 标题或整段粗体；标题和字段也保持普通字重。行动和原因各用简短的一句话，避免长段落。

步骤标题必须带与当前行动相符的图标，例如 🔎 检查、🛠️ 实施、🧪 验证、👥 独立验收、⏳ 等待或 🚧 阻塞；「做什么」与「为什么」分别用 🎯 和 💡 标识。图标不能代替文字。用具体中文任务名，必要时附技能名；不要只写「执行 scd-quickdev」或「处理中」。行动和原因各用一句话，原因应结合当前任务说明目的、要消除的不确定性或要避免的风险，不用「因为流程要求」代替解释。只提供用户可理解的简短理由，不输出内部推理链。

宿主不支持引用块时，回退为普通三行文字，仍保留图标、数字步骤和两个字段，不增加装饰边框或粗体。必须注明当前第几步，默认用「第 N 步：具体任务名」，实际输出时把 N 替换为数字。按当前任务已展示的实际步骤从 1 连续编号，进入新的有意义步骤才递增；同一步进度更新沿用原编号，切换子技能不重置。恢复任务时先核对已有编号，无法核实时明确以本次恢复为编号起点。总步数已确定时显示「第 N/M 步」；总步数未知时只显示「第 N 步」，不编造总数、百分比或固定流程。

## 何时更新

- 技能启动后的首个实际步骤，以及阶段切换、方向变化、等待用户或遇到阻塞时展示；切换技能时说明新行动为何需要。
- 同一步内连续的工具调用不重复展示；已有提示完整覆盖当前行动时不再补发相同提示。
- 等待或阻塞时说明缺失什么、为什么影响推进，以及下一行动；保留已有确认请求，不把解释当作用户授权。
- 用户明确要求更简洁或其他样式时遵从其要求；简短单步回答只需一个紧凑提示，不人为拆步骤。

本规则只调整用户可见的沟通，不替代原有确认、权限、验收或交付门；最终交付仍报告实际结果与证据，不重放所有步骤。
