# 工程最佳实践契约

本契约为跨技能共享工程基线：架构设计（`scd-architecture`）、接口契约（`interface-contract.md`）、工程实施（`scd-quickdev`）、再工程（`scd-reengineering`）与独立验收（`scd-test`）按各自触达边界按需读取对应章节，不把细则整段复制进主 `SKILL.md`。

> **最高护栏（防过度工程与防越界）**：
> - 严禁为了套用“解耦/设计模式”对**只使用 1 次或单点逻辑**强行引入接口、抽象工厂或空壳包装层；L0 局部小修以清晰直白为先。
> - 只约束**本次任务新增或修改的代码与接口边界**；发现 Issue 范围外存量耦合或技术债时只作记录（按需交由后续 `scd-maintenance`），**严禁借重构越界改造无关模块**。

## §1 架构与模块边界（高内聚 / 低耦合）

1. **按业务变化轴内聚**：把密切相关的数据结构、核心不变式校验与状态流转放到同一内聚模块；拒绝无边界的 `utils/`、`helpers/`、`common/` 垃圾抽屉，拒绝因按技术层机械切碎导致的跨文件散弹式修改。
2. **单向依赖与零循环依赖**：依赖方向必须指向稳定核心（入口/UI/Transport → 用例编排 → 领域核心规则 ← 持久化/外部适配器）。严禁核心领域模块反向依赖 HTTP 框架、CLI、UI 组件或具体 ORM；严禁引入模块间循环依赖。
3. **边界防腐层（ACL）**：外部 API 载荷、第三方 SDK 类型与数据库存储模型只在边界适配层完成一次映射，不将其原始结构直接穿透进入核心领域逻辑或公共返回契约。

## §2 接口与边界契约工学

1. **边界一次解析、内部可信（Parse, Don't Validate）**：在系统或公共接口入口集中完成类型解析、必填项、范围约束与权限校验，把结果收敛为明确类型；核心逻辑内部不重复防御性判空或猜测输入形状。
2. **窄接口与显式语义**：只暴露消费方实际所需的最小参数与返回字段。同一函数或接口出现超过 2 个布尔开关参数组合分支时，改为显式模式枚举或命名选项对象；不回传内部数据库异常名或调试栈。
3. **显式错误语义分级**：明确区分“输入校验失败 / 业务不变量冲突 / 外部依赖可重试瞬态失败 / 不可恢复系统错误”，保留调用方恢复所需的机器可读错误码。
4. **锁与事务最小化**：数据库事务、文件锁或关键状态锁内**严禁**穿插外部 HTTP 请求、LLM 调用或大块同步阻塞 IO；跨系统写入或状态变更边界须先明确幂等键或并发控制策略。

## §3 编码实施纪律与最新文档门

1. **新功能开发：先查锁版、再读最新官方文档**：凡引入或调用第三方库、SDK、框架特性、CLI、插件或平台协议，实施与定案前必须：
   - **先查本地锁定版本**：核对仓库 `package.json`/lockfile/`pyproject.toml`/`go.mod` 等确认当前实际版本（如需升级大版本须先展示变更并取得用户确认，不得私自偷升）；
   - **优先查阅最新官方文档或源码**：阅读对应版本最新官方文档、官方迁移指南/Changelog 或已安装类型与源码声明并记录适用版本；**严禁凭训练记忆臆造 API 参数或沿用已废弃接口**；
   - **受限诚实降级**：若当前处于离线或文档源不可访问环境，优先核对本地已安装依赖的类型/源码，并在方案和验收中显式标为 `UNVERIFIED`，绝不假称“已查阅最新文档”。
2. **复用先于复制**：在写出两段相似分支、校验或映射前，先搜索仓库既有 helper 并提取单一事实源，差异通过参数化或查表统一处理。
3. **浅嵌套与早返回**：使用卫语句尽早失败或返回，控制单函数分支深度与职责单一性；主流程保持清晰的步骤编排，细节下沉到命名准确的局部函数。
4. **显式失败与资源清理**：错误须处理或向上传递，不得静默吞没；打开的连接、子进程、临时文件、工作树、定时器与订阅句柄须保证异常路径下成对清理；不遗留未用参数、死分支或测试后门。
5. **复用目标仓库既有静态检查**：仓库已配置 linter、formatter、typecheck、循环依赖或安全检查时必须运行通过，不通过新增抑制注释（如 `eslint-disable`、`@ts-ignore`、`# noqa`）掩盖新债务。

## §4 `code-review` 6 条结构反模式门禁

实施自检与 Blind-First 独立验收复核真实 diff 时，重点拦截以下 6 类直接可指证的结构反模式（发现任一项实质违背均应拦截修复，不得放行合并）：

1. **空 `catch` 吞错 / 静默伪成功**：捕获异常后空置、仅打印日志却返回兜底默认值假装成功；
2. **业务规则克隆重复**：同一校验、转换或分支判断在本次 diff 或紧邻代码中被复制超过一次；
3. **跨层逆向依赖或新环依赖**：核心域反向引用入口/UI/具体存储细节，或新增模块循环依赖；
4. **事务/热循环内重型外部 IO**：在事务块或循环中发起网络请求、同步阻塞或 N+1 查询；
5. **上帝函数与失控嵌套**：单个新增/修改函数承担多个无关联阶段或出现深层嵌套分支；
6. **死代码与多余抽象层**：引入未引用的兼容开关/死路径，或为仅调用 1 次的简单逻辑强造空壳接口与工厂。
