# SCD 仓库维护

开始执行前必须先读取并遵守[步骤沟通](../scd-quickdev/references/step-communication.md)；直接调用本技能也适用。

从仓库证据发现可维护性问题，仅修复有边界、有理由的一组问题；权威方向明确前，广泛审计保持只读。设计或实施前读[计划确认契约](../scd-quickdev/references/planning-contract.md)（只读查询/审计不建计划，保持更窄治理权限）。

## 选择操作

- **审计：** 检查、评估或列出债务，只产出发现，不修改文件。
- **修复：** 明确要求清理、修复、统一或删除时，重验目标发现、判断权威并实施最小连贯修复。
- **聚焦：** 针对具名文件、子系统或债务类别检查该范围及直接消费者。

广泛修复先审计并推荐第一批不超过三个发现（不将“清理仓库”视为无边界重写）。若涉及项目级重构、语言/框架/架构替换或跨多交付分阶段迁移，改用 `scd-reengineering`（Maintenance 可提供证据，但不负责再工程方向或执行图）。

## 从仓库事实出发与审计已触发表面

1. 阅读 `AGENTS.md`、`CLAUDE.md`、仓库说明、清单、测试、CI、公共文档与原生检查工具，保留无关变更，排除生成产物、缓存与忽略文件。
2. Node.js 可用时运行确定性收集器：`node <this-skill>/scripts/collect-signals.mjs --root <repo> --format json`（仅作线索，识别损坏链接、无效 npm scripts 与 TODO/FIXME/HACK/XXX）。
3. 广泛审计或一致性判断前阅读 `references/audit-contract.md`。先运行确定性检查，再只对声称对应的文档与实施做语义比较（代码可以执行不代表代码自动正确），覆盖已触发的产品/交付契约、公共 API/CLI/配置、README/链接、架构依赖方向、死代码/冗余路径与工具可度量依赖漂移。

生成有证据支持的发现：每个发现记录稳定 `MAINT-...` 标识、类别与严重度、冲突声明、精确文件、行号、符号、命令或运行时证据、权威推断、置信度与最小修复验证路径。区分已确认债务和调查线索，不得把风格偏好、文件年龄或臆测重构报为债务。默认只在回复输出，用户要求文件时复制完成 `assets/maintenance-report.md`。

## 修复选中发现与交接

修复多个发现或删除代码/文档前阅读 `references/repair-contract.md`。编辑前针对当前工作区复现并删去不可复现项，判断权威来源（规范契约、可执行行为或说明性文档）；涉及产品行为、兼容、数据、权限或契约先澄清，具体技术方案也按计划契约确认（已批准选择不重问，只读审计不建计划）。

然后把有边界的变更交给 `scd-quickdev`：除非权威要求否则保留公共行为，同一变更内同步更新直接耦合测试/示例/文档，使用仓库机械工具并运行最强聚焦验证；暴露更大产品或架构决策时停止并报告。除非明确要求，不得自行暂存、提交、推送、发布、部署、迁移在线数据或建外部 Issue。

审计报告列明范围、运行检查、分级已确认发现、线索与盲区；修复报告列明已解决发现、变更位置、验证、延期项与不确定性，不得声称仓库“零技术债”。
